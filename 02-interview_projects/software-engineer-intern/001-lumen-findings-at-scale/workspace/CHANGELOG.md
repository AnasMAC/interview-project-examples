# Changelog

All notable changes to Tidewright Orchestrator. Versions follow semantic
versioning for the public API (`/v1`). Dates are release dates (UTC).

## Unreleased

- Added: findings in `GET /v1/findings` and `GET /v1/findings/{id}` carry
  `asset_hostname`, so a dashboard no longer needs a call per asset to show
  hosts. Requested by Lumen Retail's dashboard team (@twrona).
- Changed: `Finding.asset` joins on the tenant as well as the asset id, so a
  finding can never resolve to another tenant's asset (@twrona, review
  @karakawa).
- Changed: index cleanup on findings. Migration `0002` drops
  `ix_findings_tenant_id_last_seen_at`, redundant with
  `ix_findings_tenant_id_status`; every observed finding moves `last_seen_at`,
  so the index cost an extra write per finding per scan (@sbrandao, @lhaddad).
- Changed: report generation no longer joins the asset onto every finding
  row (@meilin).
- Changed: `make bench` times the list cases only; pass `--exports` to time
  the CSV exports as well (@meilin).

## 1.9.2 (2026-10-02)

- Fixed: the worker heartbeat thread could stop after a database reconnect,
  letting the reaper requeue a job that was still running (@aowusu).
- Fixed: `GET /v1/findings/{id}/events` returned events newest first; it now
  returns them oldest first as documented (@twrona).
- Bumped `tzdata` to 2024.2.

## 1.9.1 (2026-09-24)

- Fixed: `X-RateLimit-Remaining` was off by one on the last allowed request
  of a window (@twrona).
- Fixed: archiving an asset with a pending scan left the scan `queued`
  forever; `request_scan` now refuses archived assets with `409` (@aowusu).

## 1.9.0 (2026-09-14)

- Added: `scans.scheduled_slot` and a unique index on
  `(profile_id, asset_id, scheduled_slot)`. Running two scheduler replicas
  during the August deploy had planned some slots twice (@aowusu).
- Added: scheduler look-back window (`TW_SCHEDULER_LOOKBACK_S`) so a
  restarted scheduler plans the slots it missed (@aowusu).
- Changed: migrations squashed into one baseline (`0001_initial_schema`).
  Existing databases are stamped, not migrated (@lhaddad, @rmenon).
- Changed: `make test` runs against `tidewright_test` and Redis db 15 and is
  safe under any `COMPOSE_PROJECT_NAME`; CI runs several stacks in parallel
  (@rmenon).

## 1.8.0 (2026-08-24)

- Added: `python -m app.cli replay-job` (dry run unless `--yes`) and `prune`
  for on-call (@meilin).
- Added: outbox rows go `dead` after `TW_WEBHOOK_MAX_ATTEMPTS` instead of
  retrying forever; `delivered_at` is recorded (@meilin).
- Changed: per-plugin timeout configurable per profile (`options.timeout_s`)
  (@karakawa).

## 1.7.0 (2026-08-03)

- Changed: **the finding fingerprint now includes `location`**, normalized
  (header names lower case, `./` stripped from paths). Northpeak Health
  reported that two DEMO keys leaked in two different config files of one
  asset showed up as a single finding; removing one file marked it fixed while
  the other secret was still there. The same happened for one advisory
  matching two installed versions of a package. Fields are now joined with an
  ASCII unit separator instead of `|`. A data migration recomputed every
  fingerprint and kept triage on the rows it could map (@sbrandao).
  ADR 0002 has not been updated yet.

## 1.6.0 (2026-07-06)

- Added: reports API (`POST /v1/reports`, `GET /v1/reports/{id}`,
  `/download`) with JSON, CSV and HTML output, generated by the worker
  (`app/reporting/`, written by Yusuf Demir during his internship) (@meilin).
- Added: new CSV exporter `app/reporting/csv_export.py` with asset id, triage
  and `fixed_at` columns and spreadsheet formula neutralization.
- Deprecated: `app/reporting/legacy_csv.py`. `python -m app.cli
  export-findings` still writes the old layout because two customers import it
  with scripts.
- Removed: `page` / `per_page` query parameters (deprecated in 1.5).

## 1.5.0 (2026-05-11)

- Changed: **list endpoints paginate with `limit` and `offset`** and return
  `{"items", "total", "limit", "offset"}`. `page` / `per_page` still work in
  this release and answer with a `Deprecation` header (@twrona).
- Added: `since` filter on `GET /v1/findings` (`last_seen_at >= since`,
  offset required).
- Added: `triage` filter on findings.

## 1.4.0 (2026-03-30)

- Added: webhooks (`/v1/webhooks`) delivered through a transactional outbox
  with HMAC-SHA256 signatures (`X-Tidewright-Signature`), see ADR 0003
  (@lhaddad, @aowusu).
- Added: per-tenant rate limit (fixed window in Redis), `X-RateLimit-*`
  headers (@twrona).
- Added: `mockhook` receiver for local development (@rmenon).

## 1.3.0 (2026-02-23)

- Added: scheduled scans. Profiles take a five-field `schedule_cron`
  evaluated in the tenant's time zone (@aowusu).
- Added: `secrets_in_config` plugin; matches are redacted before they are
  stored (@karakawa).
- Added: `tenants.timezone`.

## 1.2.0 (2026-01-19)

- Added: pagination on every list endpoint with `page` and `per_page`.
- Added: findings filters `severity`, `status`, `asset_id`, `plugin`.
- Added: `PATCH /v1/findings/{id}` for triage (`accepted_risk`,
  `false_positive`) with an audit event; triage survives later scans.
  `GET /v1/findings/{id}/events` returns the audit trail (@sbrandao).
- Added: admin API for tenants and tokens (`/v1/admin/tenants`) (@twrona).

## 1.1.0 (2025-12-08)

- Added: `dependency_audit` plugin against `fixtures/advisories.json`, our
  curated advisory list with `TWSA-<year>-<nnnn>` ids (Tidewright Security
  Advisory); the advisory id is the finding's `rule_id` (@karakawa).
- Added: `POST /v1/scans/{id}/cancel`.
- Added: finding lifecycle `fixed` / `reopened` when a completed scan no
  longer reports a finding or reports it again (@sbrandao).

## 1.0.0 (2025-11-17)

First release for design partners (Acme Shipping).

- Assets, scan profiles, scans and findings over `/v1` with per-tenant API
  tokens (`tw_demo_` prefix, salted SHA-256 at rest).
- Plugins `http_headers`, `tls_config`, `open_ports`.
- Postgres job queue with heartbeats and a reaper (ADR 0001); findings
  deduplicated by fingerprint (ADR 0002).
- Docker Compose development stack, `make setup` / `make test`.
