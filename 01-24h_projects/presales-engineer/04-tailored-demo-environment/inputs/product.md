# Fictional Lantern product facts

These facts are authoritative for this exercise. Anything not stated here is unknown. Do not present it as available.

- **P1 — Mobile analysis.** Static and dynamic analysis of customer-authorized Android (APK/AAB) and iOS (IPA) builds. iOS dynamic analysis needs a development or ad-hoc signed IPA. App Store-encrypted IPAs support static analysis only. Third-party dependencies are detected in mobile builds and can be exported as a CycloneDX SBOM.
- **P2 — Web analysis.** Authenticated DAST of customer-authorized web apps and REST APIs, with OpenAPI 3 import. Authentication uses a recorded login sequence or a static bearer token. Logins protected by MFA need a test account with MFA disabled, or a token. There is no source-code SAST for web repositories. GraphQL has **no specific testing**: a GraphQL endpoint is scanned only as generic HTTP.
- **P3 — Findings.** Severity is critical/high/medium/low/info. Status is open, confirmed, false_positive, fixed or risk_accepted. Severity guides prioritization; it does not prove exploitability. A status set on a finding carries over to later scans of the same app when the same finding is detected again. Scans do not guarantee a secure app and do not provide compliance certification.
- **P4 — Reporting and exports.** Dashboard with per-app and portfolio risk trends across scans. Exports in JSON, CSV and SARIF 2.1.0.
- **P5 — Integrations.** Jira Cloud (two-way status sync), Slack webhook, GitHub Actions, GitLab CI, Jenkins, and Azure DevOps through the CLI. ServiceNow is **exploring** with no committed date.
- **P6 — CLI (v3).** `lantern scan mobile --file <path> --plan <name>` and `lantern scan web --target <url> --auth <profile>`. `--wait` blocks until done, up to a 60-minute maximum, then exits 2. `--fail-on <severity>` sets the threshold. `--baseline <scan_id>` reports only findings new relative to a baseline scan. Exit codes: 0 = completed with no open or confirmed finding at or above the threshold; 1 = completed with at least one such finding; 2 = scan error or timeout; 3 = authentication or configuration error. The API key is read from `LANTERN_API_KEY`. A typical mobile scan takes 20–45 minutes; a typical web scan takes 30–90 minutes.
- **P7 — Plans.** Team: up to 5 apps, no SSO. Enterprise: SAML SSO (no SCIM), with custom data retention of 30–365 days (default 365). Pricing is quoted only by the account executive, Noor. Solutions Engineers cannot quote prices or authorize discounts.
- **P8 — Hosting.** SaaS only. Each tenant is in the EU (Frankfurt) or US region, chosen when the tenant is created. No on-premises or air-gapped option. Data is encrypted at rest and in transit.
- **P9 — Assurance.** A SOC 2 Type II report and an annual third-party penetration test summary are available under NDA, as is the sub-processor list. Lantern is **not ISO 27001 certified**; certification is in progress with no committed date. No FedRAMP.
- **P10 — AI fix suggestions.** Exploring. Not GA, no committed date, and not available to customers.
