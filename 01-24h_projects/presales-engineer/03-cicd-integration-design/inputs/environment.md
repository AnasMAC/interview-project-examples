# Kestrel Pay environment facts

Collected from Rafa (Platform Lead) and Imane (Security Lead) during the technical kickoff on 2026-10-16. Kestrel Pay is a fictional prospect. These facts are authoritative for the exercise.

- **E1, repository:** one GitLab monorepo. `android/` (Kotlin) builds a debug APK for merge requests in 6 minutes and a release AAB for nightly and release pipelines. `ios/` (Swift) builds on the `macos` runner: an ad-hoc signed IPA in the nightly pipeline and an App Store-encrypted IPA in the release pipeline. A nightly ad-hoc build takes 18 minutes. `web/` is a React single-page app served from staging. `api/` is a REST API described by `api/openapi.yaml` (OpenAPI 3.0, about 140 operations). A new `/graphql` endpoint ships in November.
- **E2, time budgets:** merge request pipelines must finish within **15 minutes** wall clock. Lint (2 min), unit tests (5 min) and the debug build (6 min) already use 13 of them. The nightly pipeline is scheduled at 02:00 UTC on `main` and must finish by 07:00 UTC. A release pipeline starts when a `v*` tag is created on a `release/*` branch and must reach the manual `publish` job within **90 minutes**.
- **E3, secrets:** company policy says production-tenant API keys are stored only as masked, protected CI variables. Protected variables are available to `main`, `release/*`, `v*` tags and scheduled pipelines on `main`. They are **not** available to merge request pipelines from internal branches or from forks. External contributors open merge requests from forks; those pipelines must still pass without secrets.
- **E4, release policy:** a release is blocked only by **new high or critical** findings compared with the last accepted release. Known findings are tracked in Jira project KPAY and must not block. The release manager, Lina, records the accepted Lantern scan IDs after each release. Current values: `rel-4.11-android` and `rel-4.11-ios` from release 4.11 on 2026-09-30. If the security gate does not complete, a release may proceed only after a successful rerun or a documented manual approval by Imane.
- **E5, staging network:** `https://staging.kestrel.test` is reachable only from the internal network, including the self-hosted runner `staging-net`. Opening it to an external service requires an allowlist request approved by Imane, which takes about five business days. No request has been filed. Staging is redeployed nightly at 01:00 UTC.
- **E6, test accounts:** the QA account `qa-auto` has had MFA enforced since 2026-10-01. A service account `ci-scanner` has a non-expiring bearer token for staging and no MFA. Two Lantern auth profiles exist in the trial tenant: `staging-qa-user` (recorded login of `qa-auto`) and `staging-ci-token` (bearer header for `ci-scanner`).
- **E7, runners:** `saas-linux` (shared, internet egress), `staging-net` (self-hosted Linux on the internal network, internet egress through a proxy) and `macos` (iOS builds). Every runner can reach the Lantern SaaS API.
- **E8, tracking:** engineering uses Jira Cloud project KPAY. Kestrel's security operations team uses ServiceNow. Job artifacts are kept for 30 days by default; `expire_in` can extend this.
- **E9, trial:** the Lantern trial tenant is in the EU region and runs from 2026-10-19 to 2026-11-02. On 2026-10-16 the draft pipeline in `current.gitlab-ci.yml` was pushed to the internal branch `trial/lantern`; it has not run. Lantern's sizing estimate for the authenticated staging web and API scan is **about 75 minutes**.
