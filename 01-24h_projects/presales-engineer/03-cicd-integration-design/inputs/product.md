# Fictional Lantern product facts

These facts are authoritative for the exercise. Do not add capabilities they do not state.

- **P1, mobile:** Lantern runs static and dynamic analysis of customer-authorized Android (APK/AAB) and iOS (IPA) builds. Scan plans: `mobile-full` (static and dynamic) and `mobile-static`. iOS dynamic analysis needs a development or ad-hoc signed IPA. An App Store-encrypted IPA gets **static analysis only**; the scan still completes and reports dynamic analysis as skipped.
- **P2, web:** Lantern runs authenticated dynamic testing (DAST) of customer-authorized web apps and REST APIs. `--openapi <file>` imports an OpenAPI 3 description so API operations are tested directly; without it the scanner only crawls from the target URL. Authentication uses an auth profile configured in the tenant: a recorded login sequence or a static bearer token header. A recorded login cannot complete MFA; use a test account without MFA or a token. There is **no source-code analysis (SAST) of web or API repositories**. A GraphQL endpoint is scanned only as generic HTTP; there is no GraphQL-specific testing and no roadmap date has been supplied.
- **P3, where scans run:** Lantern is SaaS only, with EU or US tenants. Scans run from Lantern's scanners, which connect from published Lantern egress IP ranges. The CLI only submits a scan and optionally waits for its result; it does not scan from the machine where it runs. A web target must be reachable from the Lantern egress ranges.
- **P4, CLI:** `lantern scan mobile --file <path> --plan <plan>` and `lantern scan web --target <url> --auth <profile> [--openapi <file>]`. Options: `--wait` blocks until the scan finishes, for at most **60 minutes**; `--fail-on <severity>` sets a threshold; `--baseline <scan_id>` evaluates only findings that are new compared with that baseline scan. The CLI prints one JSON result object on stdout and a summary line on stderr.
- **P5, exit codes:** `0` = scan completed and no counted finding is at or above the threshold, **or** the scan was only submitted (no `--wait`), **or** no `--fail-on` was given; `1` = completed with at least one counted finding at or above the threshold; `2` = scan error, or `--wait` stopped after 60 minutes (the scan continues server-side and its results appear later in the dashboard); `3` = configuration or authentication error detected before submission (missing or rejected API key, missing file, unknown plan or auth profile, baseline not found, invalid arguments).
- **P6, findings:** severities are critical, high, medium, low and info. Statuses are open, confirmed, false_positive, fixed and risk_accepted. Only **open** and **confirmed** findings count toward exit code 1. Severity is a prioritization label, not proof of exploitability. A scan does not guarantee a secure app or provide compliance certification.
- **P7, baselines:** a baseline must be a completed scan of the same app in the same tenant; otherwise the CLI exits 3. Findings whose fingerprint appears in the baseline are listed as `excluded_by_baseline` and never count.
- **P8, keys:** the CLI reads the API key from the `LANTERN_API_KEY` environment variable. Keys are tenant-scoped and can be created and revoked in the dashboard. A revoked key gives exit 3.
- **P9, typical durations:** mobile scans take 20–45 minutes; web scans take 30–90 minutes.
- **P10, exports and integrations:** `lantern export --scan-id <id> --format json|csv|sarif --out <path>` downloads a completed scan's results (SARIF 2.1.0). Integrations: Jira Cloud with two-way status sync, Slack webhook, and GitHub Actions, GitLab CI, Jenkins and Azure DevOps through the CLI. There is **no ServiceNow integration**; it is marked "exploring" with no committed date.
- **P11, role boundary:** a sales engineer cannot commit roadmap items, dates or contract terms. Items marked "exploring" must not be presented as planned.
- **P12, mock:** `inputs/lantern_mock.py` imitates `lantern scan` offline using a scenario file. It applies P4–P8 and is authoritative for the exercise. It does not implement `lantern export`.
