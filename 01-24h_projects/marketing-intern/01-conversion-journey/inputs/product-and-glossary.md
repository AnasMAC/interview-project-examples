# SignalDesk facts and glossary

All entities and facts are fictional assessment data. IDs below are the authoritative sources as of exercise day 0.

| ID | Approved fact |
| --- | --- |
| P1 | SignalDesk lets a team collect manually uploaded CSV security findings into a shared queue and assign an owner. |
| P2 | The pilot supports CSV uploads only. There is no automatic scanner connection, remediation, or live risk prediction. |
| P3 | A guided demo lasts 20 minutes and uses synthetic examples. A demo is not a trial account or security assessment. |
| P4 | Pilot audience: SaaS operations teams of 3–20 people that already collect security findings. Team size means the operations team, not total company headcount. |
| P5 | Demo requests receive a human reply within two business days. There are four demo slots in the current exercise week, of which three are already reserved. |
| P6 | Pricing and public trial availability have not been approved. No certification, quantified time saving, customer count, or security guarantee is supported. |
| P7 | Contact data is used only to coordinate the requested demo. Marketing updates require a separate optional choice, unchecked by default. |

Glossary: **security finding** = an observation that might need investigation; it is not automatically a proven vulnerability. **Triage** = organizing findings, deciding what needs attention, and assigning responsibility. **Remediation** = fixing a problem; this product does not do it. **SaaS** = software provided as a service. **Conversion** = the chosen action a visitor completes. **CTA** = a call to action, such as a labeled request button. **Business day** = Monday–Friday in this exercise, with no holidays. **Consent** = an explicit choice to allow a specified use; demo coordination and marketing updates are different uses.
