# FenceNote release sheet — source R, version 2

Entirely fictional assessment facts; version 2 is approved for this launch.

| ID | Approved launch fact |
| --- | --- |
| R1 | FenceNote 0.8 imports manually uploaded CSV findings, preserves the supplied severity label, and lets coordinators assign an owner and due date. It does not discover vulnerabilities or repair them. |
| R2 | This release highlights identical finding IDs from the same uploaded file for human review. It does not automatically merge records or identify duplicates across files. |
| R3 | Users can export the current queue as CSV. PDF reports and ticket-system integrations are not released. |
| R4 | Pilot is invitation-only for operations teams of 5–25 people that already collect findings. Operations team size is not company headcount. Requests receive a reply within three business days; acceptance is not guaranteed. |
| R5 | The launch CTA offers a 20-minute guided demo using synthetic data. It offers no account, trial, assessment, or fixed start date. |
| R6 | Pricing, certifications, uptime commitments, and region-specific storage guarantees are not approved facts for this launch. |
| R7 | The release is available to invited pilot teams on exercise day 0. The product owner is Mara; the evidence reviewer is Inez; the copy approver is Jules. All names are fictional. |

Glossary: **finding** = an observation for investigation, not necessarily a verified vulnerability. **Severity** = the priority label in the uploaded source; the product preserves rather than validates it. **Duplicate** = two records that may refer to the same issue; a matching ID is a clue, not proof. **Pilot** = limited invitation-only use. **General availability** = open access; this release does not have it. **Absolute claim** = “all,” “always,” or “guaranteed,” demanding stronger evidence than the inputs provide. **Evidence boundary** = which audience, context, feature, and result a source actually supports.
