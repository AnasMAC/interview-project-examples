# HarborBoard fictional event policy

All names, times, addresses, and facts are synthetic assessment data. Do not contact anyone or connect a platform.

| ID | Authoritative rule |
| --- | --- |
| V1 | Event: “Who owns the next action?” A 30-minute educational webinar on **2026-11-05 at 15:00 UTC**, displayed locally as **16:00 UTC+01:00**. Registration closes **2026-11-04 at 12:00 UTC**. |
| V2 | There are three seats and no initial reservations. A valid request before close confirms a seat if available, otherwise enters an explicit event waitlist. Contact address and agreement to event coordination are required; name and separate marketing opt-in are optional, unchecked by default. |
| V3 | Contact identity is `contact_id`; repeated requests for the same identity do not create another seat or reset permissions. An email-like value needs one `@`, nonempty local part, and a domain containing a dot; this local rule is not a production validator. Invalid values consume no seat. |
| V4 | On cancellation, release the seat and offer it to the oldest valid waitlisted contact at that timestamp. Hold the seat for **two hours** while invited; invitation uses capacity but is not confirmation. Timely acceptance confirms it. After two hours without acceptance, expire the offer, release the hold, and offer the next eligible waitlisted contact. The expired contact stays unconfirmed and may rejoin the end of the waitlist if they explicitly request before close. |
| V5 | No new registration/waitlist entry or promotion may start at or after close. An offer issued before close may still be accepted until its stated two-hour expiry, even if expiry is after close. Existing confirmed seats remain valid. A cancellation after close releases capacity but does not trigger a new offer. |
| V6 | Event coordination consent allows only necessary confirmation, waitlist, cancellation, reminder, and event-resource messages in this exercise. Marketing updates require separate opt-in. A marketing unsubscribe does not cancel registration or remove event coordination consent; no marketing should be queued afterward. A canceled contact receives cancellation acknowledgment but no later reminder/no-show follow-up. This is an exercise policy, not legal advice. |
| V7 | Reminder is scheduled at 2026-11-05 14:00 UTC, only for confirmed contacts with event coordination consent. Post-event resource follow-up is planned for 2026-11-06 10:00 UTC, separately worded for attended/no-show confirmed contacts. Unknown attendance is held for review. No follow-up may contain a recording link until the recording is marked ready; a hold queue is acceptable, without inventing availability. |
| V8 | HarborBoard manually imports CSV findings and assigns owners/next actions. It does not discover vulnerabilities, remediate, or guarantee compliance. Webinar education does not require product use. Optional product CTA requests a 20-minute guided synthetic demo, not a free trial. |
| V9 | Event coordinator Fara owns seats, operational messages, and anomalies; content reviewer Dev owns factual/template approval; asset owner Len owns recording readiness. They are fictional. Draft messages need Dev approval plus CTA/accessibility checks before they are marked sendable. |

Glossary: **state** = current status, such as confirmed or waitlisted. **Trigger** = an event/time causing a state transition. **Seat hold** = temporary capacity reservation pending acceptance. **Nurture** = a relevant sequence of communications; it does not imply marketing permission. **CTA** = a labeled next action. **Suppression** = a rule preventing a message from entering the sendable queue. **No-show** = a confirmed registrant known not to have attended. **Idempotent** = replaying the same event/request does not duplicate effects. **UTC offset** = the difference from UTC; 15:00 UTC plus one hour is 16:00 UTC+01:00.
